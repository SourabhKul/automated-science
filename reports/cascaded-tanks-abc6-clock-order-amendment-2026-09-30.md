# ABC6 clock-failure order evidence — proposed operational amendment

**Status: independent design GO; no code or campaign GO.** This amends only terminal/replay evidence semantics for the unused `ct-abc6-20260928-v1` synthetic control. It changes no science, prior, target, simulator, ABC kernel, baseline, roster or resource cap. The one-use claim remains consumed even if a clock or terminal publication fails.

An independent fake-child review found that clock-independent process cleanup can work while the durable terminal still lacks a watchdog intervention event after persistent UTC failure. Current replay can read that missing event as if no intervention preceded a score. Missing time evidence cannot establish order. Preserve the 70/70 fake-only cleanup result as a component diagnostic, but keep the two-file patch and campaign on HOLD until this contract is implemented and independently replayed.

## Proposed terminal and event contract

The future campaign requires **terminal `schema_version: 2`**; replay must reject terminal v1 for that run. The existing acknowledgement remains schema v1 because it binds the terminal's exact bytes, digest and file identity, independent of terminal fields. Terminal v2 adds exactly one top-level object `intervention_capture` with keys `status`, `attempted_type`, `attempted_stage`, and `failure_kind`; it retains the existing `watchdog_intervention` field. Their allowed combinations are:

| `status` | `attempted_type` / `attempted_stage` | `failure_kind` | `watchdog_intervention` |
| --- | --- | --- | --- |
| `not_attempted` | both `null` | `null` | `null` |
| `recorded` | valid strings equal to event `type` / `stage` | `null` | exact typed event with valid same-host `monotonic_ns`; `occurred_at_utc` is valid UTC text or JSON `null` |
| `unavailable` | valid strings | `monotonic_unavailable` or `event_snapshot_invalid` | `null` |

The valid type/stage pairs extend the current closed replay allowlist: `budget_cap` with `sampled_rss_limit_exceeded` or `wall_clock_limit_exceeded`; `operator_stop` with `watchdog_interrupted`; `watchdog_stop` with `child_exited_with_live_process_group_members`, `process_group_membership_unknown`, `unexpected_descendant_process`, `watchdog_identity_or_monitoring_error`, `watchdog_monitoring_error`, `child_exited_process_group_reap_unverified`, **or `child_runtime_attestation_timeout`**. The last pair is already emitted by the watchdog but is missing from replay's v1 allowlist; it must be added to v2, not silently renamed. Capture the attempted type and stage **before reading either clock**. A later cleanup error may change the terminal's final `stop_reason`; it must not erase the original attempted cause or event. The event's `clock` remains `host-local-monotonic-ns`; no different clock may be compared to a score event. If monotonic capture succeeds and UTC fails, retain the event with UTC `null`, never claim/fallback UTC. If monotonic capture fails or the event cannot be validated, record `unavailable` with the frozen attempted cause and bounded failure kind. A clock failure must never silently leave `not_attempted`.

For `unavailable`, replay classifies the claimed run `unreplayable` regardless of score presence or terminal failure label. Contradictory field combinations are invalid. For `recorded`, replay compares valid same-host monotonic nanoseconds even if UTC is `null`; equal times, missing score clock identity, or a different clock are `unreplayable`. A missing event under `not_attempted` does **not** prove a later intervention; it is allowed only where the retained terminal and stage evidence independently justify a result. The required classification predicates for the new schema are:

| Score chain / terminal / capture | Classification |
| --- | --- |
| Complete score and fully verified normal child exit, no attempted intervention | `complete` |
| Complete score, valid recorded intervention **before** score event | `incomplete` |
| Complete score, valid recorded budget/operator intervention **after** score event, all required score/fit/forecast links valid, no earlier child/stage failure, and direct child reaped with tracked group verified empty | `complete` despite later capped terminal; retain cap and kill/reap evidence |
| Failed score, valid recorded intervention before score failure event | `incomplete` |
| Failed score, valid recorded intervention after score failure event, verified score failure checkpoint | `failed` |
| Any score chain with capture `unavailable`, equal event times, missing score clock, or contradictory event/terminal data | `unreplayable` |
| No score chain and capture `unavailable` | `unreplayable` |
| No score chain and a valid recorded budget/operator intervention with no earlier independently verified error | `incomplete` |
| No score chain and `not_attempted` failed terminal | `failed` only for a verified nonzero observed direct-child exit with retained attestation and verified direct-child/group reap; a prechild failure without a structured failure receipt is `unreplayable` |

A recorded watchdog monitoring stop with no score is `failed` only when the terminal's stage, child/fit-gate evidence and cleanup verification establish the failure point; when they do not, replay returns `unreplayable`. For a scored failure with `not_attempted`, require the score receipt's validated failure checkpoint plus terminal/child consistency; otherwise `unreplayable`. A **normal child-exit chain** requires terminal `status=completed`, `stop_reason=child_exited`, return code zero, a verified `child_launch.observed_process` matching the approved launch/runtime identity, `kill_and_reap.child_reaped=true`, `kill_and_reap.tracked_process_group_reaped=true`, `kill_and_reap.membership_verification=verified_empty`, no reported enumeration uncertainty, and the existing complete fit/forecast/score/ACK links. A missing field is not proof of normal exit. A later budget intervention after a complete score cannot erase a prior recorded failure; replay must examine the retained event order and stage evidence, not terminal status alone. Unknown order remains `unreplayable`.

The current replay function requires both campaign claims and the complete 48-status/pre-score chain before it enters its no-score branch. That is insufficient for a genuine prechild or partial campaign stop. The v2 replay implementation must add **separate staged verifiers**, never substitute the full-chain verifier for an incomplete run:

1. **Watchdog-claim only, before child:** verify the pinned one-use watchdog claim and terminal/ACK; terminal `child_launch.observed_process`, `kill_and_reap`, and process return code are `null`. A precreated anonymous grant channel may appear in `bootstrap_grant`, but its `grant_sha256` is `null` and no durable grant record exists. Anchored-root reads verify no campaign claim, fit/baseline status, marker, target or score artifact. Under this amendment, a `not_attempted` prechild failure is always **`unreplayable`**: the current free-text `monitor_error` and `stop_reason` do not independently verify its stage, and no structured prechild failure receipt is defined. A captured budget/operator event here can be `incomplete` if its event and absence predicates verify. A future protocol may define a separate structured prechild failure receipt and make a new classification decision before launch; this amendment does not claim one.
2. **Child launched before campaign claim:** verify the watchdog claim and launch attestation, absence of the campaign claim/status/marker/target/score under the pinned root, and positive direct-child/group cleanup. A recorded budget/operator event gives `incomplete` unless an independently verified earlier child error exists. A `not_attempted` nonzero child exit gives `failed` only with verified child/cleanup evidence; unknown membership is `unreplayable`.
3. **Campaign claim with partial training chain:** verify that campaign claim and each extant fit/baseline status as a contiguous prefix of the frozen 48-receipt order, with exact identity/hash links; verify no unexpected receipt, summary out of stage, marker, prospective target or score. A valid recorded budget/operator event is `incomplete` only when no stage error is retained and cleanup verifies. If a stage error is retained, classify it as preceding intervention only when an independently validated failure event carries the **same host-local monotonic clock** and a strictly earlier value; otherwise the ordering is `unreplayable`. The current campaign failure receipt has only `failed_at_utc`, so it never satisfies that prior-error predicate. With `not_attempted`, a verified nonzero direct-child exit and verified cleanup may support `failed` as specified above; a UTC-only stage label cannot by itself prove more. Missing/contradictory order or unverified cleanup is `unreplayable`. If all 48 statuses exist, verify summary/evidence/target-free forecast only to the last durably declared stage; do not infer missing later stages. A marker without a score requires a separate post-marker failure verifier; until that gate is independently reviewed, classify it `unreplayable`.

Every stage branch still requires a canonical terminal/ACK and no-follow anchored-root checks. Any clock capture status `unavailable` overrides the staged result to `unreplayable`. These staged paths are new implementation/replay gates, not permission to launch before they are independently tested; if they remain absent, the synthetic campaign stays HOLD. This conservatively preserves failure and partial evidence without pretending that an absent campaign claim or summary is a complete chain.

An error after child start must still trigger bounded clock-independent TERM/KILL and direct-child reap/group enumeration. Its terminal records unknown elapsed timing or membership as `null`/unknown, never as verified cleanup. A failed terminal/readback must remain `unreplayable`; a successfully read-back failed terminal does not override missing ordering evidence. Keep the terminal acknowledgement bound to exact terminal bytes and identity as already declared.
