# ABC6 preclaim grant-record binding — proposed operational amendment

**Status: independent Luna design GO for bounded fake-only implementation; current pushed preclaim component is HOLD.** The reserved synthetic campaign remains unused. This changes no scientific model, data boundary, inference rule, roster or budget.

An independent fake-only probe found that preclaim replay accepted a terminal with bootstrap descriptor FD 10 and a durable grant record with FD 11 and arbitrary `bindings` plus a recomputed self-hash. The receipt was classified `failed` even though the alleged grant did not match the terminal. The preclaim replay source and tests had already been pushed as `dba16b289a61756cf4cf7c2fca5643183b6abf39` before this probe. Keep that component and all campaign launch gates on HOLD until a corrective commit is independently reviewed and synced. The fixed source-pin gate still prevents a production campaign claim; no real or prospective target was accessed.

## Required link

For the future campaign, use a distinct **terminal `schema_version: 3`** and add `grant_record_sha256` to the exact `bootstrap_grant` object. Terminal v2 is retained as historical fake-only component evidence, not silently reinterpreted. The new field is JSON `null` when no grant record was durably issued. The authority writer must compute the digest from the exact canonical bytes it durably writes, then verify bounded bytes and stable file identity through its pinned no-follow receipt-root descriptor. Its one-use channel captures and retains that immutable publication snapshot **before** delivering the anonymous grant frame to the child; after successful delivery, `publish()` returns the retained snapshot to the watchdog. If delivery fails after durable publication, the terminal must retain the publication digest and record delivery failure, without claiming successful delivery. If the publication snapshot cannot be preserved or verified, the run is unreplayable; do not emit a contradictory terminal. The watchdog retains the snapshot through terminal publication; its terminal-time readback must equal it. It must never first learn or replace the expected digest from a terminal-time read. Do not launch another child or reuse the run ID after any such failure. The one-use claim remains consumed.

Replay must read the grant record through its anchored no-follow descriptor and require its raw-byte SHA-256 to equal the terminal's `grant_record_sha256`. A present record with a missing/null terminal digest, or a non-null digest with an absent record, is `unreplayable`. The record's `grant_fd` must equal terminal `bootstrap_grant.descriptor_fd`; its `grant_sha256` must equal the terminal's secret digest. Validate the `bindings` exact field set and types with the reviewed `ABC6AuthorityBindings` schema. Reject any mismatch. Preserve the strict no-child branch: a precreated anonymous channel may have descriptor metadata but no grant digest, no grant-record digest, and no durable grant record.

**Trusted expected bindings are a separate input, not derived from the grant file or terminal.** Extend the frozen replay identity with an optional typed `expected_child_grant_bindings: ABC6AuthorityBindings`, required when a grant record exists and absent for a prechild/no-grant path. The caller must construct it from the independently frozen manifest/review/approval, the anchored receipt-root identity, a separately read and verified preexisting watchdog claim, and watchdog-captured child launch/observed-process attestation. Dynamic watchdog/child PID and start IDs must be corroborated against those separately verified process observations; a terminal field alone is insufficient. If those observations are unavailable after termination or their provenance cannot be checked, production replay is unreplayable until a reviewed launch-time attestation receipt or equivalent trusted source is in place. Replay compares the record's entire validated `bindings` payload to this expected object, field for field, including `review_sha256`, full source/runtime rosters, child/watchdog start IDs, and role entrypoints. If this expected object is unavailable or any field differs, the child-grant stage is `unreplayable`; it cannot yield a trusted `failed` or `incomplete` preclaim classification. The frozen object's existing protocol/run IDs, manifest/approval hashes, Git HEAD, claim hash, receipt-root identity and three integrated source hashes must also agree with the corresponding expected fields. Independently verify the fields observable in the terminal, process attestation and anchored filesystem against the expected object. A merely self-hashed `bindings_sha256` is never authority. This is an explicit new caller contract: the current production manifest/review/source closure cannot yet supply it, so production replay remains fail-closed until those separate gates are reviewed. A fake fixture may supply a synthetic expected object only for fake-only tests, never for a real campaign.

The publication-time raw digest proves the later receipt is the same bytes the authority writer issued; the independently supplied expected bindings prove the recorded values match the frozen run. A valid terminal/ACK alone does neither. Never reconstruct `expected_child_grant_bindings` from terminal, grant record, or an unreviewed score receipt. If the source of any expected field cannot be established independently, return `unreplayable` and leave production on HOLD; do not downgrade the check to digest-only or claim full provenance from byte consistency.

The terminal ACK remains v1 and binds the terminal's exact bytes/file identity; it is not a substitute for the new grant-record digest. Replay for this unused campaign must require terminal v3, while retaining v2 only for explicitly labeled historical fake fixtures if needed. The final immutable manifest and independent review report must pin v3; no launch may use a mutable schema interpretation.
