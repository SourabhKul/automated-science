# ABC6 direct-entrypoint permit gate — proposed fake-only contract

**Decision draft, 2026-10-02T05:49Z.** This addresses a material authorization gap that source hashes alone cannot close. It authorizes only independently reviewed fake-only implementation and tests after design GO. It does not authorize a campaign claim, ABC/Qwen run, prospective synthetic target generation, real `yEst[768:1024]`, official `uVal/yVal`, manifest approval or launch. Reserved `ct-abc6-20260928-v1` remains UNUSED/HOLD.

## Observed bypass and scope

The integrated runner currently consumes watchdog startup authority and passes it into the evidence campaign. Both public campaign APIs still have a direct no-authority path: the status-only API accepts no authority argument, while the evidence API defaults to `launch_authority=None`. After final source pins are filled, that path can create a campaign claim and training evidence under an empty-root check. `begin_training()` does not yet require runner startup. The scorer has an O_EXCL one-use reveal marker but accepts no watchdog-issued scoring permit. It can receive an execution object from a direct campaign path; the marker proves ordering, not authority. These are synthetic-methods paths, not access to the real tank or official test targets. The current `None` source pins make them preclaim fail closed today, but are not a future authorization control. Audit evidence: `core/real_data/cascaded_tanks_abc6_campaign_fit.py:2914-2985`, `core/real_data/cascaded_tanks_abc6_authority.py:950-957`, `core/real_data/cascaded_tanks_abc6_scoring.py:2384-2600`, `scripts/run_cascaded_tanks_abc6_synthetic.py:459-583`.

The frozen case-role tuple names `core/real_data/cascaded_tanks_abc6_cases.py::get_training_case_data`, but that function is absent. The existing public `ABC6TrainingBundle.data_for_case()` returns data without a permit; `run_abc6_training_case(data)` accepts caller-supplied arrays and is exported. A future trusted campaign must not infer per-case authorization from either one. The generic simulator and offline numerical helpers may remain available for synthetic controls, but cannot create a trusted campaign status, execution or scoring eligibility without the authenticated permit chain. This is a trusted-local-checkout methods gate, not a sandbox against arbitrary Python code.

## Frozen phase and entrypoint rules to review

1. **Runner startup.** The only production route to campaign execution is a sealed `ABC6LaunchAuthority` received from the watchdog's exact manifest/root/runtime-bound grant. `run_cascaded_tanks_abc6_synthetic` consumes runner startup once before source preflight. `begin_training()` must reject an authority whose runner startup has not been consumed, and remains one-use. Manifest/source preflight may be read-only without a grant, but must never create a campaign claim or simulate a production case.
2. **Both public campaign APIs.** Make `launch_authority` mandatory and non-null for `run_abc6_training_campaign_with_evidence`; reject missing, wrong-type, stale or mismatched authority before the first claim or training simulator call. It calls `begin_training()` once as its first supervised action. The status-only `run_abc6_training_campaign` must require the same authority and **delegate directly to the evidence entrypoint**, returning its `campaign_result` without its own `_execute_campaign` route. `_require_role()` checks the immediate function frame, and the frozen campaign role names only the evidence entrypoint; a separate status-only `begin_training()` call would fail the role contract. No failure or alternate API grants a second training session for the same authority/run ID.
3. **Per-case data and fit.** The evidence entrypoint calls `session.issue_case_permit(index)` itself for each ordered index 0..23, as the frozen campaign role's immediate function frame; it passes the resulting exact 24 permits to the private execution path. Preissuing all permits before preflight/claim consumes this training session even if preflight fails; no same-ID retry or reissue is allowed. Add the exact frozen case-role function `get_training_case_data(bundle, case_index, permit)` in the already rostered cases module. That function itself calls `permit.consume(case_index)` so the immediate role check succeeds, verifies the exact frozen bundle identity, and returns a new private-sealed `ABC6AuthorizedCaseData` carrying that same authority, index, bundle identity and original case data. The exported production `run_abc6_training_case` accepts **only** this sealed object, atomically consumes its fit-once flag before numerical work, verifies its authority remains live and its case data is still the referenced bundle's exact object, then calls the numerical fitter. A reused, copied, reconstructed, cross-authority or swapped-bundle value fails before simulation; use a private identity registry or equivalent unforgeable in-process seal, not only dataclass field equality. Plain `ABC6TrainingCaseData` and `ABC6TrainingBundle.data_for_case()` remain offline numerical-control inputs, but cannot enter the production fit or create a campaign status. Keep a separately named private/test-only helper for caller-supplied arrays. If fit fails after either permit consumption, the index/run is terminal; no replacement permit or same-ID restart.
4. **Evidence and handoff.** The returned `ABC6TrainingCampaignExecution` retains an internal, non-caller-supplied authority/grant link and its run, manifest and anchored receipt-root identity. After `_execute_campaign` returns complete, the evidence entrypoint registers **that exact object identity** once in the authority's state, checking the grant/run/manifest/root binding; the scorer rejects `copy.copy`, dataclass reconstruction and any different object, even with equal fields. The execution constructor must be privately sealed or otherwise reject caller-created lookalikes. After all 48 ordered status receipts, terminal summary and complete target-free forecast are durable, the runner independently reopens and hashes them, calls `create_runner_handoff(execution, ...)` with exact ordered digests, and then `activate_scoring()` once. The handoff must match that registered execution identity and anchored receipts, not just digest shape. A malformed or incomplete roster cannot activate the scorer.
5. **Scorer entrypoint and reveal.** Make a sealed `ABC6ScoringPermit` mandatory for `score_deferred_abc6_synthetic`. The scorer's **first supervised action** validates the permit belongs to the exact registered execution authority/run/manifest/receipt root and consumes it once, before other fallible pre-marker evidence checks, reveal marker creation or any prospective-target simulator. A failed `activate_scoring()` call is terminal because authority already records activation attempted; a failure after permit consumption is terminal even if it occurs before the reveal marker. The existing durable marker remains an independent one-use backstop; post-marker failure remains consumed. For fake-only tests, preserve and assert the in-memory authority state for a consumed-permit/no-marker branch and the watchdog terminal failure receipt; a durable, independently replayable pre-marker score-attempt record/classification is a **separate HOLD** before production launch. An execution object, forecast digest, or locally writable marker cannot substitute for the scoring permit. Internal target materialization must be reachable only through the scorer's consumed-permit path.

Authority has existing one-use runner, case, handoff and scoring objects, but the production runner currently uses only startup and training; it does not consume case permits or activate scoring. This proposal wires those capabilities, rather than treating a source hash as authorization. Exact class seals, role path/function checks and receipt-root binding remain mandatory. A role-function change or new source file changes the reviewed source roster and requires a new immutable manifest/approval after implementation.

## Fake-only acceptance and remaining HOLDs

Under isolated temporary roots and fake-issued grants, require before-claim failures for missing/None/wrong-role/stale authority, direct status and evidence calls, unconsumed runner startup, wrong root/manifest and duplicate training. Test the status-only delegation and preissued-permit path under the frozen immediate-caller role checker; calling `issue_case_permit()` from the private loop must fail. Require before-case-fit/receipt failures for missing, wrong-index, copied, replayed and cross-authority case permits or authorized-case-data seals; prove the exact `get_training_case_data` role function exists and is the only production data route. Require before-marker/target-simulator failures for missing/cross-authority/replayed scoring permits, incomplete 48-status/summary/forecast handoff and copied execution objects; exercise consumed-permit/no-marker and failed-activation terminal states. A deliberately injected simulator sentinel must stay untouched for every rejected path. Verify one complete fake authorized path, terminal failure consumption and no duplicate claim/marker. Run current plus clean-HEAD-overlay focused tests under pinned Python, then independent Luna max exact-byte review before scoped one-owner non-force Git sync.

Do not use real/protocol prospective targets for these checks. Production source pins, typed role-specific runtime identity, source-backed replay expectation, four-state terminal-v4 replay, immutable manifest, independent report, approval and separate launch GO remain HOLD. Keep the 2026-10-02 watchdog PGID timing failures in the negative ledger; this permit gate does not repair that supervision race.
