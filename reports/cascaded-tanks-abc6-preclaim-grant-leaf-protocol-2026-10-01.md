# ABC6 campaign preclaim grant leaf — bounded contract

**Decision draft (2026-10-01T14:32Z):** permit a single durable watchdog grant record before campaign-fit claims only when the caller holds the live, process-bound training authority. This is a fake-only implementation target pending independent design review. It does not authorize a synthetic campaign, target reveal, Qwen call, or real-data access. The reserved `ct-abc6-20260928-v1` remains UNUSED/HOLD.

The current writer must still require an empty receipt root immediately before creating `watchdog-child-grant.json`; the Stage A sidecar remains in the separate claims parent. The conflict is later: campaign-fit independently scans for an empty receipt root **four times**: root open, claim entry, immediately before its durable global claim, and execution preclaim. A normal direct campaign-fit caller must retain that empty-only rule.

For the supervised path, the runner passes the **received live authority object**, never a boolean, path, copied environment locator or caller-supplied digest, to the public campaign-fit entrypoint. That exact public function must call `authority.begin_training()` **at entry, before the first root-open scan**, because the current authority checks the immediate caller's role/source/function. Retain the returned sealed session and pass it into the internal helpers for all four scans; calling `begin_training()` from an internal helper would fail the caller check. The permit is tied to the pinned physical root, protocol/run, manifest/approval/review identities, verified child PID/start/vector/image and the exact grant record. Watchdog identity was checked at grant publication and child receipt; the existing `begin_training()` check does not by itself prove the watchdog is still alive. The supervised entrypoint may then accept only the exact receipt-root listing `{watchdog-child-grant.json}` at all four scans. Prove that campaign-fit's opened root FD and the authority's retained receipt-root FD refer to the same pinned `(st_dev,st_ino)` directory, or perform all four checks through one retained descriptor; compare unchanged root identity on every check. A direct public call without that permit still requires an empty root.

At child receipt, retain the grant leaf's raw SHA-256 and the repository's `_FileId` identity `(st_dev, st_ino, st_size, st_mtime_ns, st_ctime_ns)` with the live authority, plus regular-file/mode evidence. The existing read verifies a stable no-follow file and canonical exact payload but currently discards this snapshot. At each preclaim check reopen the one fixed leaf descriptor-relative with `O_NOFOLLOW|O_NONBLOCK`; require stable regular-file status and mode, stable named entry, bounded canonical bytes, the identical five-field `_FileId`, raw SHA and exact payload/bindings matching the live authority. Any missing, extra, swapped, symlinked, malformed or changed leaf, ancestor/root identity change, stale/replayed authority, or wrong role/function fails before the campaign claim. Failure consumes the supervised attempt; it cannot be repaired by retrying the same run ID. Do not relax the watchdog writer's empty-root requirement or accept the grant by filename alone. The separate directory listing and O_EXCL claim write are not atomic against an external concurrent writer; this methods-control gate assumes the trusted local run owns its receipt root and records that assumption rather than claiming race-proof isolation.

Fake-only tests must cover direct empty-root success and direct grant-leaf rejection; supervised sole-leaf success; no/forged/stale/replayed training authority; wrong role/source/function; extra, missing, symlinked, copied, mutated or replaced grant leaf and ancestor; changed digest/stat/size/mtime/ctime/mode/bytes between receipt and **each of the four scans**; and a failure before campaign claim with no simulation or target access. Test a bounded concurrent-extra-leaf interleaving to document the ownership assumption and fail where the final scan can observe it; do not claim to prevent an untrusted writer racing after that scan.
