# ABC6 replay Stage B1: verify the claim and attestation before classification

**Decision (2026-10-01T05:50Z):** implement a bounded, fake-only verifier component. This is not production replay or launch approval. Keep terminal-v4 classification fail-closed; do not alter ABC inference, read real targets, create a campaign claim, or fill missing source pins.

## Input boundary

Use the existing anchored root and no-follow claim-parent descriptor, plus a **separate typed expectation input** for the component helper. Fake-only tests construct that expectation from fixture manifest/approval and independently declared fixture launch/runtime values, never from the claim, sidecar or grant record. The current `ABC6FrozenReplayIdentity` supplies hashes, HEAD and root identity but does **not** supply decoded manifest/approval, launch vectors, watchdog runtime, or the complete source/role roster. There is no production builder for the new input; the public replay entrypoint must remain closed to terminal v4. Accept only the exact canonical watchdog-claim schema written by the reviewed watchdog, including its exact nested `watchdog_attestation` shape. A raw claim SHA alone is insufficient. Compare the claim's declared child launch vector, executable and resolved image/digest, accepted observed `argv[0]` forms and exact argv tail, expected child image, watchdog live argv/image/runtime values, root and claim-parent identities, protocol/run, manifest, approval and reviewed HEAD to that independently supplied typed input. If a required independent source is unavailable, return an explicit unreplayable/HOLD result rather than a default.

Read `<run_id>.launch-attestation.json` from the pinned claims-parent descriptor, never a resolved arbitrary path. First validate the terminal-v4 `launch_attestation` reference itself as exactly `{leaf, sha256, device, inode, mode, size_bytes}` with exact types. Require regular-file, no-follow, stable pre/post stat and named-entry identity, the Stage A exact canonical v1 schema, 64 KiB inclusive bound, raw SHA match and `(st_dev, st_ino, st_mode, st_size)` equality to that reference. Existing replay `_FileIdentity` omits mode, so retain/check `st_mode` explicitly for this link. Compare the sidecar claim hash, root and claims-parent identity, vectors and image digests to the separately verified claim and typed expectation. The claim has no process-start fields: validate the sidecar start IDs' shape and compare to separately supplied process expectations only where available in fake fixtures. Production attribution of starts remains a later gate. Do not resample a dead PID to reconstruct an earlier start identity. Keep ACK v1's terminal raw-byte and file-identity binding unchanged.

## Stage B1 implementation boundary

Add independently callable, typed verification helpers and fake-only adversarial tests for exact claim/sidecar structure and cross-links. Preserve historical terminal-v3 semantics. Keep the public replay entrypoint rejecting terminal v4 until a separately reviewed Stage B2 integrates four-state classification and complete source-backed expected bindings. In particular, no test may imply that a sidecar or self-hashed grant record alone establishes a trusted run result.

Probe extra/missing and duplicate keys, boolean-as-integer fields, noncanonical encoding, wrong but self-consistent nested argv/image data, claim/sidecar swaps, digest/stat mismatch, symlinks, copied ancestors, and presence/absence of **this run's fixed sidecar leaf** in the shared claims parent. Unexpected receipt-root entries belong to the separate B2 branch check. Probe mismatched start identity where a fixture supplies an independent process expectation, without postmortem PID sampling. Run focused current and clean-HEAD-overlay tests under the pinned interpreter. Independent Luna review of exact final hashes is required before a sole-owner scoped Git sync.

It must preserve one-use consumption, classify incomplete evidence `unreplayable`, and verify full source-backed grant bindings before trusted outcome classification. A separate campaign-fit sole-grant-leaf exception, complete transitive source/runtime/role closure, immutable manifest/report/approval, full post-marker replay, and separate launch GO remain HOLD.
